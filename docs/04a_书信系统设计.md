# 04a — 书信系统设计

> 归属：社交与关系系统（04）子系统
> 定位：官场社交的核心基础设施，后续情报、人情债、事件触发等系统均通过书信系统流转信息
> 版本：v0.1

---

## 1. 系统定位与职责

书信系统承担以下职责：

| 职责 | 说明 |
|------|------|
| **信息传递** | 上级命令、NPC私信、情报消息均通过书信送达玩家 |
| **玩家主动社交** | 玩家可主动给任意已知NPC写信，触发AI回复 |
| **剧情推进门控** | 特定书信要求玩家在截止日前回复，否则硬阻断月份推进 |
| **关系系统钩子** | 收发、回复、忽略书信均影响与对应NPC的好感度 |
| **LLM内容载体** | NPC信件内容由LLM依据当前游戏状态动态生成 |

书信系统**不负责**截获/情报拦截（留给后续情报系统）。

## 2. 信件核心属性

### 2.1 信件类型（letter_type）

| 类型 | 中文名 | 典型场景 | 是否可回复 |
|------|--------|---------|-----------|
| `OFFICIAL` | 公文 | 上级下发指令、政策通知 | 可（奏折形式） |
| `PERSONAL` | 私信 | NPC拉拢、道贺、问候 | 可 |
| `MEMORIAL` | 奏折 | 玩家向上级汇报、请示 | 可（上级批复） |
| `INTELLIGENCE` | 情报 | 线人/密探消息、小道消息 | 一般不回 |
| `CIRCULAR` | 檄文/告示 | 一对多广播，传达政令 | **不可回复** |

### 2.2 保密等级（confidentiality）

| 等级 | 中文名 | 可见范围 | 泄露风险 | 存档行为 |
|------|--------|---------|---------|---------|
| `PUBLIC` | 公开 | 所有人可见 | 高（敏感内容写在公文里后果自负） | 永久存档 |
| `PERSONAL` | 个人 | 收发件人，可转发亲信 | 中 | 永久存档 |
| `SECRET` | 机密 | 仅收发件人，不可转发 | 低 | 永久存档 |
| `BURN` | 焚毁件 | 仅收发件人 | 极低 | **读后自动删除**（前端消失，后端保留日志） |

### 2.3 信件状态机（status）

```
DRAFT ──────────────────────────────────────────→ [废弃/不发送]
  │
  └─→ IN_TRANSIT（已发出，传递中）
         │
         └─→ DELIVERED（已送达，但未读）
                │
                └─→ READ（已读）
                       │
                       ├─→ REPLIED（已回复）
                       ├─→ ARCHIVED（已归档）
                       └─→ BURNED（焚毁件读后即此状态，前端不再展示）
```

- `DRAFT`：仅存在于玩家写信时的草稿状态；NPC发信不经过此状态
- `BURNED`：后端记录状态，前端从收件箱消失

## 3. 参与方模型

书信支持四种收发组合：

| 场景 | 发件人 | 收件人 | 触发方式 |
|------|--------|--------|---------|
| NPC → 玩家 | Agent | 玩家 | 月份推进时由 LetterService 生成 |
| 玩家 → NPC | 玩家 | Agent | 玩家主动写信 |
| NPC → 玩家（回复） | Agent | 玩家 | 玩家上封信送达后，NPC下月回复 |
| 玩家 → NPC（回复） | 玩家 | Agent | 玩家在信件详情页选择回复 |
| 系统 → 玩家（檄文） | Agent（群发） | 多Agent+玩家 | 特定游戏事件触发 |

> **檄文说明**：多收件人广播，`recipient_agent_ids` 存所有收件NPC列表；玩家不可回复，仅阅读。

## 4. 时间机制

### 4.1 送达延迟

| 情景 | 延迟（月） |
|------|-----------|
| 普通信件（默认） | +1 |
| 加急文书（is_urgent=True，消耗银两） | 0（当月即到） |
| 远途/跨省 | +2 ~ +3（按行政层级差计算） |

`delivered_month = sent_month + delivery_delay`

月份推进时，LetterService 将所有 `delivered_month <= current_month` 且状态为 `IN_TRANSIT` 的信件批量更新为 `DELIVERED`。

### 4.2 截止回复时间

- `reply_deadline_month`：最晚回复的游戏绝对月份
- `is_blocking`：是否硬阻断推进
  - `True`：调用 `advance_month` 前检查，未回复则返回 `4xx`，附信件信息，前端弹出阻断提示
  - `False`（软deadline）：超时触发后果（关系下降、错失机会），但不阻断推进
- `default_choice_id`：仅限**软deadline**使用，超时自动应用的选项 ID（硬deadline不可配置此项）

## 5. 回复机制

### 5.1 回复类型

| 类型 | reply_options 值 | 适用场景 |
|------|-----------------|---------|
| 不需要回复 | `null`，`requires_reply=False` | 情报、告示、单向通知 |
| 自由回复 | `null`，`requires_reply=True` | 私信往来、玩家写奏折 |
| 选择题回复 | 选项列表（见下方格式） | 上级指令、需要明确表态的请求 |

### 5.2 选项格式

```json
[
  {
    "id": "accept",
    "text": "遵命，下官即刻办理",
    "hint": "服从。关系+5，但执行可能损耗民心",
    "consequence_tags": ["obey", "relation_up"]
  },
  {
    "id": "decline",
    "text": "此事恐有不妥，容下官再议",
    "hint": "婉拒。可能引发上级不满，关系-8",
    "consequence_tags": ["refuse", "relation_down"]
  },
  {
    "id": "negotiate",
    "text": "下官愿意配合，但请求宽限时日",
    "hint": "拖延。deadline延后1月，关系-3",
    "consequence_tags": ["delay"]
  }
]
```

- `hint`：对玩家可见的后果提示（模糊描述，不暴露精确数值）
- `consequence_tags`：后端用于触发具体效果（关系变化、游戏状态变更）

### 5.3 回复处理流程

1. 玩家提交回复（选项 ID 或自由文本）
2. LetterService 记录回复内容，状态改为 `REPLIED`
3. 根据 `consequence_tags` 执行后果：关系变化、游戏状态修改
4. 若为玩家→NPC的信件，标记 NPC 下月生成回信
5. 若信件为焚毁件，触发 `BURNED` 状态

## 6. LLM 生成机制

### 6.1 触发场景

| 场景 | 触发时机 | 说明 |
|------|---------|------|
| NPC主动发信 | 月份推进时 | LetterService 检查哪些NPC在此月应发信 |
| NPC回复玩家 | 玩家信件送达后的下月推进时 | 自动回复，延迟1月符合游戏时间逻辑 |
| 上级批复奏折 | 玩家奏折送达后的下月 | 与NPC回复相同流程 |

### 6.2 生成上下文（generation_context）

```json
{
  "trigger": "npc_initiative | reply_to_player | superior_review",
  "sender_agent": {
    "name": "...",
    "role": "...",
    "archetype": "...",
    "relationship_with_player": 42,
    "faction": "..."
  },
  "game_context": {
    "current_month": 18,
    "recent_events": ["..."],
    "player_recent_actions": ["..."],
    "county_status_summary": "..."
  },
  "letter_type": "PERSONAL",
  "confidentiality": "SECRET",
  "parent_letter_body": "...",  // 若为回复，附上原信内容
  "requires_reply": true,
  "is_blocking": false,
  "reply_options_if_needed": [...]
}
```

### 6.3 生成约束

- 信件内容须符合明朝书信格式（文言色彩，但不必严格古文）
- 字数控制：情报类 100-200 字，私信 150-400 字，公文 200-500 字
- NPC的性格（archetype）、与玩家的关系值必须反映在语气和措辞上
- 若信件需要选择题回复，LLM 生成信件正文，选项由游戏逻辑预设（不由LLM生成）

## 7. 与社交系统的联动

### 7.1 好感度影响

| 行为 | 好感度变化 | 说明 |
|------|-----------|------|
| 玩家主动给NPC写信（非回复） | +2（对方） | 等同于"写信问候"，季度1次免费，超出消耗AP |
| 玩家及时回复NPC来信（软deadline内） | +3 ~ +5 | 视回复内容的态度而定 |
| 玩家超时未回（软deadline过期） | -5 ~ -10 | 按月累计 |
| 玩家回复选了"拒绝"类选项 | -5 ~ -15 | 取决于关系现状和拒绝强度 |
| 玩家回复选了"接受"类选项 | +3 ~ +8 | |
| NPC收到玩家奏折/汇报 | +1 ~ +3 | 上级觉得下级认真做事 |

### 7.2 社交行动表更新

在 04_社交与关系系统 第5.1节基础上，"写信问候"扩展为完整书信系统：

| 行动 | AP消耗 | 效果 |
|------|--------|------|
| 写信问候（每季度首封） | 0 | 好感+2，进入书信往来 |
| 主动写信（季度第2封起） | 1 | 好感+2，但额外消耗AP |
| 写奏折（上报） | 0 | 触发上级回复，影响考核印象 |

### 7.3 人情债触发

通过书信产生人情债的场景：
- 上级通过密信"通风报信"（情报类） → 小恩人情债
- 上级批复奏折时"力挺支持" → 中恩人情债
- NPC通过私信告知危险或重要消息 → 小恩人情债

## 8. 数据模型

```python
class Letter(models.Model):

    class LetterType(models.TextChoices):
        OFFICIAL     = 'OFFICIAL',     '公文'
        PERSONAL     = 'PERSONAL',     '私信'
        MEMORIAL     = 'MEMORIAL',     '奏折'
        INTELLIGENCE = 'INTELLIGENCE', '情报'
        CIRCULAR     = 'CIRCULAR',     '檄文'

    class Confidentiality(models.TextChoices):
        PUBLIC   = 'PUBLIC',   '公开'
        PERSONAL = 'PERSONAL', '个人'
        SECRET   = 'SECRET',   '机密'
        BURN     = 'BURN',     '焚毁件'

    class Status(models.TextChoices):
        DRAFT      = 'DRAFT',      '草稿'
        IN_TRANSIT = 'IN_TRANSIT', '传递中'
        DELIVERED  = 'DELIVERED',  '已送达'
        READ       = 'READ',       '已读'
        REPLIED    = 'REPLIED',    '已回复'
        ARCHIVED   = 'ARCHIVED',   '已归档'
        BURNED     = 'BURNED',     '已焚毁'

    game                = models.ForeignKey('GameState', on_delete=models.CASCADE)

    # 发件人（二选一：Agent 或玩家）
    sender_agent        = models.ForeignKey('Agent', null=True, blank=True,
                                            on_delete=models.SET_NULL,
                                            related_name='letters_sent')
    player_is_sender    = models.BooleanField(default=False)

    # 收件人（普通信件二选一；檄文可两者都有）
    recipient_agent     = models.ForeignKey('Agent', null=True, blank=True,
                                            on_delete=models.SET_NULL,
                                            related_name='letters_received')
    player_is_recipient = models.BooleanField(default=False)
    # 檄文专用：多收件人 Agent ID 列表
    circular_recipient_ids = models.JSONField(default=list, blank=True)

    # 内容
    letter_type         = models.CharField(max_length=20, choices=LetterType.choices)
    subject             = models.CharField(max_length=200)
    body                = models.TextField()
    confidentiality     = models.CharField(max_length=20, choices=Confidentiality.choices,
                                           default=Confidentiality.PERSONAL)

    # 时间
    sent_month          = models.IntegerField()         # 发出时的游戏绝对月份
    delivery_delay      = models.IntegerField(default=1)
    delivered_month     = models.IntegerField()         # sent_month + delivery_delay
    is_urgent           = models.BooleanField(default=False)

    # 回复机制
    requires_reply      = models.BooleanField(default=False)
    is_blocking         = models.BooleanField(default=False)
    reply_deadline_month = models.IntegerField(null=True, blank=True)
    reply_options       = models.JSONField(null=True, blank=True)   # None=自由; list=选择题
    default_choice_id   = models.CharField(max_length=50, null=True, blank=True)  # 软deadline自动选项

    # 回复内容
    reply_body          = models.TextField(blank=True, default='')
    reply_choice_id     = models.CharField(max_length=50, blank=True, default='')
    replied_month       = models.IntegerField(null=True, blank=True)

    # 状态
    status              = models.CharField(max_length=20, choices=Status.choices,
                                           default=Status.DRAFT)
    read_at_month       = models.IntegerField(null=True, blank=True)

    # 线索（往来书信链）
    parent_letter       = models.ForeignKey('self', null=True, blank=True,
                                            on_delete=models.SET_NULL,
                                            related_name='replies')

    # LLM 生成元数据
    llm_generated       = models.BooleanField(default=False)
    generation_context  = models.JSONField(null=True, blank=True)

    created_at          = models.DateTimeField(auto_now_add=True)
    updated_at          = models.DateTimeField(auto_now=True)

    class Meta:
        ordering = ['-sent_month', '-created_at']
        indexes = [
            models.Index(fields=['game', 'status']),
            models.Index(fields=['game', 'delivered_month']),
            models.Index(fields=['game', 'is_blocking', 'reply_deadline_month']),
        ]
```

## 10. 月份推进时的书信处理

`advance_month` 调用时，LetterService 按以下顺序执行：

```
1. blocking_check()
   ├── 若有 is_blocking=True 且 reply_deadline < current_month 且 status != REPLIED
   └── 抛出 LetterBlockingError，阻断推进

2. deliver_letters(current_month)
   └── IN_TRANSIT → DELIVERED（delivered_month <= current_month）

3. apply_soft_deadline_consequences(current_month)
   └── 软deadline已过且未回复 → 触发关系下降，status标记为超时

4. generate_npc_letters(current_month)
   ├── 检查哪些NPC本月应主动发信（事件驱动或定期联络）
   └── 调用 LLM 生成信件内容，创建 IN_TRANSIT 信件

5. generate_npc_replies(current_month)
   └── 找上月玩家信件已送达NPC的，调用 LLM 生成回复，创建 IN_TRANSIT 信件
```

## 11. 前端 UI 设计

### 11.1 信箱入口
- 顶部导航栏显示信封图标 + 未读数量角标（红点）
- 有 `is_blocking` 信件时，角标改为警告色（橙/红），不可忽略

### 11.2 信箱主界面（三 Tab）
- **收件箱**：发件人、主题、送达月份、状态标签（未读/待回复/已读）、保密等级标签
- **发件箱**：收件人、主题、发出月份、对方是否已读（NPC逻辑）
- **待回复**：仅显示 `requires_reply=True` 且未回复的信件，标注截止月份，紧急件置顶

### 11.3 信件详情页
- 信头：发件人（职位+姓名）、日期（游戏月份）、保密等级印章样式
- 正文（排版仿古典书信格式）
- 回复区：
  - 选择题：按钮组，每个选项附 hint 文字
  - 自由回复：文本框 + 发送按钮
- 焚毁件：读取后显示"此信已焚毁"提示，刷新后从列表消失

### 11.4 月份推进拦截
- 玩家点击"推进月份"时，前端先调用 `blocking-check`
- 若 `blocked=true`，弹出模态框：
  - 标题："有紧急公文需要处理"
  - 列出所有 blocking 信件（标题+发件人+截止日期）
  - 按钮："前往处理" → 跳转对应信件详情

### 11.5 写信界面（模态框）
- 收件人：从已知NPC列表选择（下拉/搜索）
- 信件类型：私信 / 奏折 / 公文
- 保密等级：默认"个人"，可选
- 是否加急（消耗银两）
- 主题 + 正文（支持一定字数提示）

## 12. 待解决问题（v2+）

| 问题 | 优先级 | 说明 |
|------|--------|------|
| 信件被截获机制 | 低 | 情报系统就绪后接入 |
| 玩家与NPC之间书信频率限制 | 中 | 防止玩家刷关系 |
| 信件存档/搜索 | 低 | 信件量大后需要 |
| NPC之间书信（可窥探） | 低 | 情报系统子功能 |
| 信件影响考核结论 | 中 | 与考核系统联动 |
| 写信消耗银两（纸墨、信使费） | 低 | 数值平衡调整后加入 |
