## 0. 核心设计哲学

### 玩家：由行动定义

玩家角色**没有**预设的性格属性。玩家是谁，由玩家做了什么来定义。

- 不存在"智力 7 / 合群 0.8"这样的玩家固定人设
- 玩家的声望（清名/能名/人缘/威名）完全由历次决策行为驱动
- 玩家的政治理念（社稷—黎民等）同样从中立（0.5）出发，随行为漂移——玩家在选择中塑造立场，而非出生即定
- AI 考核委员在评价玩家时，依据的是**行为记录与声望数值**，而非某个预设属性

### NPC：由属性定义

NPC 属性**预先设定**，在中期不频繁变动。

- 属性决定 NPC 的对话口吻、决策倾向、立场边界
- 属性对玩家**不直接可见**，但行为会透露线索（"此人精明"暗示高智力，"此地主嚣张跋扈"暗示高威名）
- 好感度（`player_affinity`）是唯一会因互动而持续变化的属性

## 1. 玩家属性体系

### 1.1 内在能力（隐藏，1.0–10.0，随游戏经历提升）

| 属性 | 含义 | 影响机制 | 增长触发 |
|------|------|---------|---------|
| `knowledge` | 知识：农耕/经济/地理 | 投资收益、施政判断的上限 | 经历特定事件并做出正确决策（待设计） |
| `skill` | 技能：谈判/协调 | 谈判成功率、说服 NPC 的效率 | 完成谈判事件后（待设计） |

初始值：`knowledge = 3.0`，`skill = 3.0`（统一起点，无出身差异）。

> **设计意图**：内在能力是玩家"成长"的量化体现。玩家看不到精确数值，只能感知到"你的谈判越来越顺手了"。

### 1.2 声望（半隐藏，0–100，行为驱动）

玩家声望与 NPC 声望使用同一套四维体系：

| 属性 | 含义 | 主要增减来源 | 展示方式 |
|------|------|------------|---------|
| `integrity`（清名） | 公正廉洁的口碑 | 拒绝贿赂↑，公正判案↑；接受贿赂↓，徇私枉法↓ | 5 档±偏差显示 |
| `competence`（能名） | 干练能干的口碑 | 政绩突出↑，重大施政失误↓ | 5 档±偏差显示 |
| `popularity`（人缘） | 官场和气的口碑 | 主动社交↑，履行承诺↑；弹劾他人↓，失信于人↓ | 5 档±偏差显示 |
| `authority`（威名） | 必要时强硬的口碑 | 顶压执法↑，强硬拒绝无理要求↑；一味妥协↓，软弱应对↓ | 5 档±偏差显示 |

声望 5 档分级：极低(0–20) / 低(21–40) / 中(41–60) / 高(61–80) / 极高(81–100)。
展示时有 ±10 随机偏差，使玩家无法精确判断实际值。

初始值：`integrity = 50`，`competence = 30`，`popularity = 10`，`authority = 40`。

> **威名的设计意图**：威名不是"暴君式"的属性，而是代表"在关键时刻是否敢于亮出底线"。高威名的玩家在与地主谈判、应对无理胡闹时更有底气；低威名则容易被各方得寸进尺。

### 1.3 政治理念（半隐藏，0.0–1.0，从 0.5 出发随行为漂移）

玩家与 NPC 共用同一套三维理念体系，但玩家的理念**不是预设的**，而是从中立点出发，由每次关键决策的选择塑造：

| 属性 | 低值（<0.3）倾向 | 高值（>0.7）倾向 | 典型触发行为 |
|------|----------------|----------------|------------|
| `state_vs_people`（社稷—黎民） | 优先百姓福祉 | 优先完成上级指标 | 主动减税赈灾→降低；顶压上缴→升高 |
| `central_vs_local`（集权—分权） | 重视地方自主 | 恭顺朝廷旨意 | 绕过知府自行决策→降低；严格执行指令→升高 |
| `pragmatic_vs_ideal`（现实—理想） | 坚守原则不妥协 | 务实灵活接受妥协 | 宁可亏损也不行贿→降低；接受灰色方案→升高 |

初始值：三维均为 `0.5`（中立，无立场偏向）。

> **理念的游戏意义**：
> - 理念影响特定情境下 AI NPC 对玩家的感知与态度（如社稷倾向的知府更欣赏完成指标的玩家，黎民倾向的耆老更信任关心百姓的玩家）
> - 理念影响年终考核委员的评分倾向
> - 理念本身对玩家**不直接展示**，但玩家可以通过 NPC 的反应间接感知"你越来越务实了"

### 1.4 仕途与个人财富

| 属性 | 含义 | 变化时机 |
|------|------|---------|
| `career_track.rank` | 品级（七品→六品→...） | 大考升迁时 |
| `career_track.candidate_pool_level` | 候选池等级（0–3） | 年度考评后 |
| `personal_wealth` | 家产（两） | 每月薪俸积累、灰色所得 |

### 1.5 玩家属性总览

```
PlayerProfile
├── knowledge               # 内在能力·知识（隐藏，初始3.0，可增长）
├── skill                   # 内在能力·技能（隐藏，初始3.0，可增长）
├── integrity               # 声望·清名（行为驱动，初始50）
├── competence              # 声望·能名（行为驱动，初始30）
├── popularity              # 声望·人缘（行为驱动，初始10）
├── authority               # 声望·威名（行为驱动，初始40）
├── state_vs_people         # 政治理念·社稷—黎民（初始0.5）
├── central_vs_local        # 政治理念·集权—分权（初始0.5）
├── pragmatic_vs_ideal      # 政治理念·现实—理想（初始0.5）
├── personal_wealth         # 家产（初始0.0）
└── career_track            # 仕途轨迹（in county_data）
    ├── rank                # 品级
    ├── term_index          # 任期编号
    ├── candidate_pool_level
    └── pool_entry_log[]
```

## 2. NPC 属性体系（统一规范）

### 2.1 核心能力（1–10，整数）

| 属性 | 含义 | 游戏影响 |
|------|------|---------|
| `intelligence` | 智力 | 决策质量，识破谎言，处理复杂问题的能力 |
| `charisma` | 魅力 | 影响他人的能力，社交效能，拉拢和游说 |
| `loyalty` | 忠诚 | 对玩家或其派系的依附程度，抗拉拢能力 |

> 玩家不能直接看到这些数值，但可以通过交互和传闻间接感受。

### 2.2 性格三维（0.0–1.0，0.5 为中点）

> **命名约定**：维度格式为「**低值极端 — 高值极端**」。即第一个词对应低值端（<0.3），第二个词对应高值端（>0.7）。

| 属性 | 低值（<0.3） | 高值（>0.7） |
|------|------------|------------|
| `sociability`（**孤僻—合群**） | 独来独往，不在乎评价，难以拉拢 | 善于社交，易受舆论影响，可被拉拢 |
| `rationality`（**感性—理性**） | 凭直觉和情感决策，容易被感动或激怒 | 数据驱动，冷静算计，不容易被感动 |
| `assertiveness`（**温顺—强硬**） | 为人温和，善于妥协，不轻易强硬 | 性格坚定，寸步不让，直接表态 |

**注意**：`assertiveness` 描述的是「遇压是否退让」，而非「是否爱出风头」——它决定 NPC 在谈判/对抗中的软硬程度，与声望维度 `authority`（威名）存在正相关但独立：威名是外部口碑，assertiveness 是内在性格。

### 2.3 政治理念三维（0.0–1.0，与玩家共用同一套维度）

| 属性 | 低值（<0.3） | 高值（>0.7） | 影响 |
|------|------------|------------|------|
| `state_vs_people`（社稷—黎民） | 优先百姓福祉 | 优先国家利益和君主意志 | 税收执行，赈灾态度，对玩家施政风格的认可度 |
| `central_vs_local`（集权—分权） | 支持地方自主 | 恭顺朝廷旨意，强化中央 | 对政策态度，派系选择 |
| `pragmatic_vs_ideal`（现实—理想） | 坚守原则，不惜代价 | 务实灵活，接受妥协 | 面对灰色问题时的选择 |


### 2.4 声望四维（0–100，与玩家共用同一套维度）

NPC 声望为**预设值**，不因玩家互动而改变（NPC 间互动引起的变化在后续版本中考虑）。

| 属性 | 含义 | 典型高值 NPC 示例 |
|------|------|-----------------|
| `reputation.integrity`（清名） | 公正廉洁的口碑 | 正直的耆老，廉洁的官员 |
| `reputation.competence`（能名） | 干练能干的口碑 | 精明的师爷，干练的知府 |
| `reputation.popularity`（人缘） | 受众好感的口碑 | 和蔼的耆老，亲民的里长 |
| `reputation.authority`（威名） | 令人畏惧的口碑 | 强势地主，铁面官员 |

### 2.5 目标体系

NPC 目标有两种表示形式，服务不同用途：

**叙事目标**（字符串列表，用于 LLM Prompt 注入，使对话更自然）：
```python
"goals": [
    "辅佐县令治理好一方",
    "积累政绩以求日后出仕",
]
```

**决策目标**（权重字典，用于 AI 知县等自主决策的量化评分）：
```python
"goals": {
    "welfare": 0.25,    # 造福百姓
    "reputation": 0.20, # 名誉声望
    "power": 0.30,      # 权力升迁
    "wealth": 0.15,     # 财富积累
    "legacy": 0.10,     # 留名后世
}
```

> 对话型 NPC（师爷、地主等）使用叙事目标；AI 知县（邻县自主决策）使用决策目标。

### 2.6 好感度与记忆

| 属性 | 取值 | 含义 |
|------|------|------|
| `player_affinity` | -99 ~ 99（默认 40–60） | 对玩家的整体态度 |
| `memory` | 字符串列表（最多 20 条） | 重要交互事件摘要，注入 Prompt |

## 4. 固定 NPC 角色卡

### 4.1 核心县衙 NPC（FULL tier，LLM 驱动对话）

**沈清远 — 师爷**
- 定位：游戏助理 + 新人引导 + 策略顾问
- 限制：每季度可问策 `advisor_level` 次（默认 1），超出拒绝回答
- 特权：注入「治县要略」游戏规则知识
- 建议风格：定性分析（"百姓怨声渐起"），不透露精确数值
- 初始好感：60
- 声望示意：清名高、能名高、人缘中、威名低

**周正卿 — 县丞**
- 定位：县衙副手，第二幕僚
- 无问策次数限制，可随时交谈
- 特权：注入「治县要略」，与师爷相同
- 建议风格：保守务实，循规蹈矩
- 初始好感：55
- 声望示意：清名中、能名中、人缘中、威名低

### 4.2 地方 NPC（LIGHT tier，规则 + 按需 LLM）

**李秀才 — 耆老**：民间舆论风向标，正直仁厚，重教化；清名高、人缘高、威名低

**张铁根 — 里长**：基层民意代表，朴实直率，关心税负；人缘中、威名中

### 4.3 知府（由官场体系生成）

知府作为玩家的直属上级，**不在固定 NPC 角色卡中预设**，而是在游戏创建时由官场体系（`officialdom.py`）与其他官员一同随机生成。知府的姓名、人设（bio）、属性和关系网络均通过 `MagistrateService` + LLM 动态产生，以确保每局游戏的上级 NPC 具有独特性格，避免玩家形成"固定攻略"。

> 知府角色的行为逻辑详见 `01b_AI决策系统.md`。

每局游戏创建时，根据县域数量按村生成**地主 + 村民代表**各 1 名，角色名随机生成，性格由 persona 模板决定。

### 5.1 地主 Persona（6 种）

|------------|------|---------|---------|
| `clan_elder_landlord` | 宗族大户 | 持重老练，根基深厚，中庸之道 | 中 |

## 6. AI 知县（邻县/非玩家控制县令）属性

AI 知县是特殊 NPC：不与玩家直接对话，而是**自主做出施政决策**。其属性存于 `county_data.governor_profile`，独立于 `Agent` 模型。

```
governor_profile
├── intelligence            # 智力（1–10）
├── personality
│   ├── sociability         # 合群—孤僻
│   ├── rationality         # 理性—感性
│   └── assertiveness       # 沉默—张扬
├── ideology
│   ├── state_vs_people     # 社稷—黎民
│   ├── central_vs_local    # 集权—分权
│   └── pragmatic_vs_ideal  # 现实—理想
├── goals                   # 决策目标权重字典
│   ├── welfare
│   ├── reputation
│   ├── power
│   ├── wealth
│   └── legacy
└── memory                  # 决策记忆（最多 8 条）
```

AI 知县额外有三个元数据字段（存于 `county_data.governor_meta`）：

```
governor_meta
├── name          # 知县姓名（如"陈文博"）
├── bio           # LLM 生成的人物简介
├── style         # 施政风格：minben/zhengji/baoshou/jinqu/yuanhua
├── archetype     # 道德类型：VIRTUOUS/MIDDLING/CORRUPT
└── county_name   # 所辖县名
```

## 7. 关系网络

### 7.1 数据结构

`Relationship` 模型（双向，`agent_a` / `agent_b`）：

| 字段 | 含义 |
|------|------|
| `affinity` | 好感度（-99 ~ 99） |
| `data.type` | 关系类型标签（同乡/政敌/同门/宗族/恩情/竞争等） |
| `data.desc` | 关系说明文本（注入 Prompt） |

### 7.2 初始化规则

- **固定关系**：`MVP_RELATIONSHIPS` 预设核心 NPC 间的关系
- **动态本地关系**：按 persona_id 组合自动生成村内地主↔村民代表、地主↔耆老/里长的关系
- **上层官员关联**：特定县域类型（`fiscal_core`/`clan_governance`）会为强势地主生成与府级/省级官员的庇护关系（patronage/kinship）

## 8. 玩家属性成长机制（草案，暂缓实施）

> ⚠️ **状态：设计草案，暂不实施。** 优先级低于威名机制、司法系统、年度考核等核心系统。待上述系统稳定后再回头实现。

> **核心原则**（来自 GDD 4.2）：内在能力不因简单重复而增长，而是"**在错误后做对**"时才增长。成长是偶然性奖励，不是打怪刷经验。

### 8.1 成长触发条件

| 属性 | 触发类型 | 触发条件 | 增量 |
|------|---------|---------|------|
| `knowledge` | 投资决策 | 本年某投资首次失败（如水利冲毁），下一年同类型成功 → 增长 | +0.2 |
| `knowledge` | 灾害应对 | 第一年灾害未应对好（民心大跌），第二年同类灾害应对成功（有义仓/赈灾）→ 增长 | +0.15 |
| `knowledge` | 税率判断 | 连续两年税率过高导致人口外流后，主动下调并稳住人口 → 增长 | +0.1 |
| `skill` | 谈判 | 同类谈判（兼并/水利/隐田）**上一次失败，本次成功** → 增长 | +0.25 |
| `skill` | 谈判 | 委托师爷/县丞谈判失败后亲自完成 → 增长 | +0.15 |
| `skill` | 司法 | 首次卷宗判决引起民心/治安负面波动，后续判决趋于平稳 → 增长 | +0.1 |

### 8.2 实现要点

**状态追踪**：在 `county_data` 中记录一个 `growth_events` 字典，用于识别"失败后成功"的配对。

```python
county_data['growth_events'] = {
    'last_negotiation_result': {'ANNEXATION': 'failed', 'IRRIGATION': None, 'HIDDEN_LAND': None},
    'last_disaster_response': {'flood': 'poor', 'drought': None},
    'last_irrigation_attempt': 'washed_out',  # 本次投资结果
}
```

**增长上限**：`knowledge` 和 `skill` 上限均为 `10.0`，每次增量小（0.1–0.25），三年任期内理论最大增长约 1.5–2.0，即从 3.0 → 约 5.0。

**玩家感知**：不显示精确数值，仅在达到整数阶梯时给出叙事提示（如"你在与地主的周旋中愈发游刃有余"），或在下次相同情境中，师爷评语略有不同。

**knowledge 的游戏效果**（待细化）：
- 投资建筑的实际效益有 ±(3 - knowledge/10) × random() 的随机误差，knowledge 越高误差越小
- 灾害预判事件中，knowledge 越高越容易识别隐性风险提示

**skill 的游戏效果**（待细化）：
- 谈判基础胜率加成：`skill_bonus = (skill - 3.0) * 2%`（3.0 时 +0%，6.0 时 +6%，10.0 时 +14%）
- 委托师爷/县丞代谈的成功率受 skill 影响

## 9. 威名（authority）游戏抓手 — 详细实施方案

### 9.1 设计原则

威名不是暴力属性，而是"**已知的底线**"。高威名意味着地方各方都清楚这位知县关键时刻不会退缩，由此产生两个对称效应：
1. **对手在谈判中预期更高的强制执行风险** → 谈判胜率提升
2. **被强势地主反弹上报** → 招致上级压力，年度考核受损

### 9.2 初始值与变化规则

**初始值：`authority = 40`**（v1.2 从 20 调整至 40，给新手县令一个有意义的起点）

| 触发行为 | 变化量 | 触发位置（代码） |
|---------|--------|----------------|
| 强制清丈隐匿土地（地主拒绝申报，强制执行） | **+1** | `negotiation.py::_apply_hidden_land_outcome`，当 `decision != 'declare_all'` |
| 强制征收地主余粮（紧急状态下动用） | **+5** | `emergency.py::force_levy_gentry_grain`，成功征收后 |
| 年度自然衰减（每年正月结算） | **−1** | `settlement_seasonal.py::_credit_annual_stipend` 同处，或新增 `_decay_authority` |

**取值范围**：0–100（超出则 clamp）。

> **设计意图**：清丈 +1 是小幅累积（需要多次才有感），强征 +5 是重大动作奖励（同时也是最高冲突行为）；年度衰减 -1 代表没有持续作为则威名逐渐淡化。

---

### 9.3 效果一：谈判威慑（authority ≥ 60 注入 Prompt）

#### 触发条件
- 玩家 `authority >= 60`
- 谈判类型：`ANNEXATION`（兼并）、`HIDDEN_LAND`（隐田）、`IRRIGATION`（水利）

#### Prompt 注入方式（Option C — 定性描述）

采用定性文字而非数字百分比，避免数字精度假象和 60 阈值处的概率跳变：

| 威名区间 | 注入文本 |
|---------|---------|
| < 60 | 不注入（`authority_hint` 为空） |
| 60–75 | `【关于县令】此人素有雷厉风行之名，必要时不惜动用官府强制手段。` |
| 76–100 | `【关于县令】此人在本地以铁腕著称，强制执行几乎是其惯常手段。` |

#### 实现位置

- `negotiation.py` 模块顶部：`_authority_tone(authority: int) -> str`
- `negotiate_round()` 中构建 ctx 后：`ctx['authority_hint'] = _authority_tone(game.player.authority)`
- `prompts.py` 三个谈判 template 的 `{round_pressure}` 行下方插入 `{authority_hint}`

---

### 9.4 效果二：强势地主上报（authority ≥ 60 触发概率检查）

#### 触发条件（全部满足时才检查概率）

| 条件 | 说明 |
|------|------|
| 谈判类型为 `ANNEXATION` 或 `HIDDEN_LAND` | 仅对抗型谈判，水利出资谈判不触发 |
| 玩家**赢得**谈判 | `decision == 'stop_annexation'` 或 `decision == 'force_survey'`（强制清丈） |
| 玩家 `authority >= 60` | 威名未到 60 不触发 |
| 地主 `reputation.authority >= 55` | 地主本身有门路，才有能力上报 |

#### 上报概率公式

```python
def _gentry_complaint_prob(player_authority: int, gentry_authority: int) -> float:
    """地主向上打报告的触发概率。"""
    base = (player_authority - 55) * 0.008
    # authority=60 → base=4%；authority=80 → base=20%；authority=100 → base=36%
    gentry_factor = max(0.0, (gentry_authority - 50) * 0.004)
    return min(0.40, base + gentry_factor)
```

#### 触发后效果

1. **写入 EventLog**（玩家**不可见**，后台记录）
   ```python
   EventLog.objects.create(
       game=game,
       season=game.current_season,
       event_type='gentry_complaint',
       category='GENTRY_COMPLAINT',
       description=f'{agent.name}通过关系向上级传达了对当前知县施政方式的不满',
       data={
           'agent_name': agent.name, 'village_name': village_name,
           'player_authority': player_authority,
           'gentry_authority': gentry_rep_authority,
           'trigger': session.event_type,
       },
   )
   ```

2. **累计投诉计数**（存于 `county_data`）
   ```python

   ```

3. **年度考核扣分**（在 `annual_review.py` 的知府主观分计算中读取）
   - 每次投诉：知府主观分 −5，上限 −15（即 3 次以上不再继续扣）
   - 年终清零计数（每年独立计算）

4. **年度小考等级下调**（仅当 `prefect_complaints >= 3` 时）
   - 在 `AnnualReviewService.ensure_prefecture_self_reviews()` 中读取投诉数，将 LLM 生成的 grade 强制下调一档
   - 优→良，良→中，中→差（差不再下调）

5. **信号泄露（可选，增加游戏张力）**：在下次玩家与师爷对话时，如果当年已有 ≥ 2 次投诉，师爷 memory 中注入一条隐性记忆 "坊间有议论，说大人行事过刚，已有人上达天听"。实现方式：在 `AgentService.build_system_context` 中读取 `county['prefect_complaints']` 后动态追加。

#### 代码改动点

**`negotiation.py::_apply_annexation_outcome` / `_apply_hidden_land_outcome`** — 在写入 EventLog 之后，追加：

```python
cls._check_gentry_complaint(game, session, county, agent, decision)
```

**新增私有方法 `NegotiationService._check_gentry_complaint`**：

```python
@classmethod
def _check_gentry_complaint(cls, game, session, county, agent, decision):
    """强势地主在对抗型谈判中被压制后，检查是否向上级打报告。"""
    winning_decisions = {'stop_annexation', 'force_survey'}
    if decision not in winning_decisions:
        return
    try:
        player_authority = game.player.authority
    except Exception:
        return
    if player_authority < 60:
        return
    gentry_rep = (agent.attributes.get('reputation') or {})
    gentry_authority = int(gentry_rep.get('authority', 0))
    if gentry_authority < 55:
        return

    prob = _gentry_complaint_prob(player_authority, gentry_authority)
    if random.random() > prob:
        return

    # 记录投诉
    county['prefect_complaints'] = county.get('prefect_complaints', 0) + 1
    save_player_state(game, county)
    village_name = agent.attributes.get('village_name', '')
    EventLog.objects.create(
        game=game, season=game.current_season,
        event_type='gentry_complaint', category='GENTRY_COMPLAINT',
        description=f'{agent.name}通过关系向上级传达了对当前知县施政方式的不满',
        data={
            'agent_name': agent.name, 'village_name': village_name,
            'player_authority': player_authority,
            'gentry_authority': gentry_authority,
            'trigger': session.event_type,
        },
    )
```

## 10. 清名（integrity）游戏抓手 — 贿赂响应

### 10.1 设计原则

清名代表"公正廉洁的口碑"，是官场评价体系中最直接受道德行为影响的维度。每一次面对贿赂时的抉择，都会留下口碑痕迹——接受是污点，拒绝是加分。

### 10.2 初始值与变化规则

**初始值：`integrity = 50`**

| 触发行为 | 变化量 | 触发位置 |
|---------|--------|---------|
| 拒绝行贿（任意类型） | **+1** | `views.py::RespondBribeView`（玩家）；`bribery.py::process_ai_village_bribe`（AI） |
| 接受行贿（任意类型） | **−5** | 同上 |

**取值范围**：0–100（clamp）。

> **设计意图**：拒绝贿赂的回报是小幅累积（+1），接受一次的代价是拒绝五次才能补回（−5），体现"廉洁一世，一贿尽毁"的现实逻辑。

### 10.3 玩家路径实现

在 `views.py::RespondBribeView` 的 accept/reject 分支后：

```python
if player_profile:
    if accept:
        player_profile.integrity = max(0, player_profile.integrity - 5)
    else:
        player_profile.integrity = min(100, player_profile.integrity + 1)
    player_profile.save(update_fields=['integrity'])
```

### 10.4 AI 路径实现

在 `bribery.py::process_ai_village_bribe` 的 accept/reject 日志处，同步更新 `county['governor_integrity']`（初始值若缺失则视为 50）：

```python
# 接受
county['governor_integrity'] = max(0, county.get('governor_integrity', 50) - 5)
# 拒绝
county['governor_integrity'] = min(100, county.get('governor_integrity', 50) + 1)
```

`governor_integrity` 可在知府视察报告、年度考核 AI 风评中读取，作为辅助参考。
